NeoForge : interpretation

NeoForge apparait haut car il dispatch les events et capabilities des mods. Dans ces profils, le cout vient surtout des listeners appeles par NeoForge, pas d'un calcul interne evident a patcher globalement.
  • firePlayerTickPost : procedures cosmeticarmoursmod / cosmeticweaponsmod.
  • fireEntityTickPost/Pre : Accessories, Curios, Artifacts, Mowzie's Mobs, Twilight Forest.
  • fireServerTickPost : Mekanism, FluxNetworks, holograms, Lootr, SophisticatedCore.
  • fireLevelTickPost : Create logistics.

Conclusion

  • Le patch RS/Mekanism reduit bien les methodes ciblees.
  • Le plus gros gain visible est sur Refined Storage transmitters : environ -90%.
  • Mekanism baisse surtout sur le registry transmitter : environ -35%.
  • Le serveur reste limite par Create, les block entities et plusieurs events player/entity.
  • Un patch NeoForge global n'est pas recommande sans cible plus locale.

Sources et methode

Fichiers analyses : postpatchinstall.sparkprofile, Patchinstallandon.sparkprofile, patchinstallbutmekanism-refined-off.sparkprofile.

Les profils ont ete decodes localement depuis le format Protobuf Spark. Les pourcentages par methodes representent leur poids dans le Server thread sur l'echantillon. Pour les piles d'appel imbriquees, les pourcentages ne doivent pas etre additionnes comme une consommation exclusive exacte.
